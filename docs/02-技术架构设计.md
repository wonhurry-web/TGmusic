## 1. 技术选型

| 层次 | 技术 | 选型理由 |
| --- | --- | --- |
| 构建工具 | Vite 8 | 启动快、HMR 迅速、生态成熟 |
| 视图框架 | React 18 | 组件化、生态丰富、并发特性 |
| 语言 | TypeScript | 类型安全，便于大型迭代维护 |
| 状态管理 | Zustand | 轻量、无 Provider、API 简洁，符合「轻量」定位 |
| 图标 | lucide-react | 轻量 SVG 图标，tree-shaking 友好 |
| 样式 | CSS Variables + 原生 CSS Modules | 零运行时开销，主题切换基于变量，性能好 |
| 移动端路由 | 单页面 + 浮层/抽屉状态 | 符合「单主页面」设计，无需重型路由 |
| 原生打包 | Capacitor | Web 代码复用，支持 Android，ADB 调试友好 |
| 本地存储 | localStorage / Capacitor Preferences | 设置、时长统计持久化 |

## 2. 分层架构

```
┌──────────────────────────────────────────────┐
│                  视图层 (React Components)     │
│  MainPage / Header / Tabs / Chat / Settings   │
├──────────────────────────────────────────────┤
│                  状态层 (Zustand Stores)       │
│  useTheme / usePlayer / useChat / useSettings │
├──────────────────────────────────────────────┤
│                  服务层 (Services / Adapters)  │
│  musicApi / chatService / syncService         │
├──────────────────────────────────────────────┤
│                  数据层 (Data / Storage)       │
│  mockData / localStorage / Preferences        │
└──────────────────────────────────────────────┘
```

- **视图层**：只负责渲染与交互，不直接处理数据源。
- **状态层**：全局状态，组件通过 selector 订阅。
- **服务层**：对外暴露统一接口；当前返回 Mock，后续替换为真实 API。
- **数据层**：持久化与 Mock 数据。

## 4. 状态管理设计

采用 Zustand，按领域拆分 store：

| Store | 状态 | 操作 |
| --- | --- | --- |
| `useThemeStore` | `mode`（light/dark/colorful） | `setMode()`、持久化 |
| `usePlayerStore` | 当前歌曲、播放状态、进度、队列、已听时长 | 播放控制、队列操作、时长累加 |
| `useChatStore` | 频道消息列表、未读数、会话开关 | 发送消息、标记已读、打开频道 |
| `useSettingsStore` | 音质、账号、FRP、离线开关 | 各设置项切换、持久化 |

> 设计原则：store 只暴露最小必要 API，UI 通过 selector 精确订阅，避免无关渲染。

## 5. 主题系统

**基于 CSS 自定义属性（CSS Variables）**，在 `:root`、`[data-theme="dark"]`、`[data-theme="colorful"]` 下定义不同的变量值。组件只引用语义化变量（如 `--color-bg`、`--color-primary`），主题切换只需改变 `document.documentElement.dataset.theme`，无需重渲染组件树。

```
data-theme = "light"     → 白底黑字（默认）
data-theme = "dark"      → 黑底白字
data-theme = "colorful"  → 渐变背景 + 彩色强调 + 光效
```

主题偏好持久化到 localStorage，启动时读取并应用。

## 6. API 解耦策略

- 所有数据访问经过 `services/` 层。
- 定义统一接口（如 `MusicApi`），当前由 Mock 实现。
- 后续接入真实 API 时，只需新增适配器实现同一接口，在 service 工厂中切换，UI 层零改动。
- 详见 [数据模型与 API 规划](04-数据模型与API规划.md)。

## 7. 性能策略

| 策略 | 说明 |
| --- | --- |
| 轻量依赖 | 仅引入必要库，图标按需引入 |
| CSS 变量主题 | 无运行时样式计算开销 |
| 组件 memo | 列表项 `React.memo`，减少重渲染 |
| 精确订阅 | Zustand selector 按需订阅 |
| 列表虚拟化 | 歌曲列表量大时预留虚拟滚动接入点 |
| 图片懒加载 | 封面图 `loading="lazy"` |
| 按需加载 | 浮层/面板懒挂载 |
