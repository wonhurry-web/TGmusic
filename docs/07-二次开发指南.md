### 2.3 两条关键数据流

**一起听同步**：
```
本地操作（加入/置顶/切歌）→ player store 变更 → useSync 检测（applyingRemote=false 才发）
  → syncService.queueSync/trackSync → 服务端广播 → 其他端 on('queue'/'track')
  → applyingRemote=true → applyRemoteQueue/applyRemoteTrack → UI 更新
```

**在线频道**：
```
ChatPanel 输入 → chat.sendText → syncService.sendChat('text', ...)
  → 服务端校验+生成（sender=join 时登记的真实用户）→ chat:message 广播（含自己）
  → useSync on('chat') → chatStore.receive（按消息 id 去重，self=sender.id===本机uid）
```

> 频道与同步共用一条 WS 连接、由设置「一起听同步」开关统一控制；**不要**在客户端做本地乐观插入或机器人回复——服务端是唯一消息权威。

## 4. 常见改造任务操作路径

### 4.1 新增同步消息类型（例：同步播放进度）

1. `server/src/protocol.js`：`MSG` 加常量（如 `PROGRESS: 'progress:sync'`）。
2. `server/src/server.js`：`handle()` 加 `case MSG.PROGRESS: return onProgress(ws, ctx, msg);` 并实现处理函数（校验 → `broadcast(...)`）。
3. 客户端 `src/services/syncService.ts`：`MSG` 表加同名常量；服务端下发分支加 `case` → `this.emit('progress', ...)`；上行封装 `sendProgress()`。
4. `src/hooks/useSync.ts`：`on('progress', ...)` 接到目标 store。
5. `server/test/sync.test.js` 仿照现有用例补一条广播测试，`npm test`。

### 4.2 新增音乐数据源（例：接入网易云）

1. `src/types/index.ts` 确认 `Track` 结构（`id/title/artist/cover/duration/source`）。
2. 新建 `src/services/neteaseApi.ts`，实现与 `musicApi.ts` 抽象一致的方法（`search / playlists / tracks / lyrics / playurl`）。
3. `src/services/resilientApi.ts` 降级链插入该源（直连优先，失败降代理再降 Mock）。
4. 服务端如需代理：`server/src/musicRoutes.js` 加路由、`server/src/cache.js` 定缓存 TTL。

### 4.3 新增设置项（例：聊天消息通知开关）

1. `src/store/settings.ts`：state 加字段 + setter（已有持久化中间件自动落 localStorage）。
2. `src/components/SettingsPanel.tsx`：加 UI 行（用现有 `Toggle` 组件）。
3. 消费方直接 `useSettingsStore((s) => s.xxx)`。

### 4.4 修改播放顺序规则（消耗式推进）

核心是 `src/store/player.ts` 的模块级纯函数 `advance(queue, current)`：
- 已播曲出队 → 有置顶则跳置顶第一首 → 否则按原顺序环回 → 仅剩一首则清空停止。
- **改规则只动这个函数**；手动下一首/上一首与音频 `ended` 自动切歌都走它。先写纯函数用例再改 UI，真机验证路径见 CHANGELOG 0.4.1。

### 4.5 新增聊天消息类型（例：贴图）

1. 服务端 `src/protocol.js`：`CHAT_KINDS.add('image')`。
2. 服务端 `onChatSend`：对该 kind 的 content 做对应校验（如 URL 白名单）。
3. 客户端 `src/types/index.ts`：`MessageType` 联合类型加 `'image'`；`ChatPanel.tsx` 加渲染分支与发送入口。
4. `sync.test.js` 补用例。

### 4.6 换酷狗凭据 / 重新生成证书

- 凭据：`curl -X POST http://127.0.0.1:8788/api/credentials/template` 生成 `server/data/credentials.json` 后编辑；或环境变量 `KG_USERID/KG_TOKEN/KG_MID/KG_DFID`。
- 自签证书（同步用）：重新生成 `server/certs/cert.pem|key.pem`（SAN 需含域名+节点IP+局域网IP），并把新 `cert.pem` 覆盖到 `android/app/src/main/res/raw/sync_cert.pem`，重新打包 APK。

### 4.7 改完代码如何发布到真机

```bash
npm run build                                            # 1. 前端构建
cp -r dist/* android/app/src/main/assets/public/         # 2. 同步产物（覆盖式拷贝）
cd android && export JAVA_HOME="D:/ai项目在这/音乐app/tools/jdk21/jdk-21.0.13+9"
"D:/ai项目在这/音乐app/tools/gradle-8.11.1/bin/gradle" assembleDebug --no-daemon   # 3. 打包
adb install -r app/build/outputs/apk/debug/app-debug.apk # 4. 安装
```

服务端改动则只需重启：`cd server && npm start`（或 `TLS_ENABLED=1 npm start`）。

## 5. 避坑清单（实测踩过的坑）

| 坑 | 现象 | 正解 |
| --- | --- | --- |
| **端口 6666** | App 内 WS 一直连不上，CDP 抓包见 `net::ERR_UNSAFE_PORT` | Chromium 禁用 6665-6669；主端口用 **8788**，6666 仅作 frp 兼容 |
| **自签证书不生效** | 直连 IP 的 wss 失败，域名却正常 | 证书信任要写进 `network_security_config.xml` 的 **`base-config`**（IP 直连不走 domain-config）；cert 与 `res/raw/sync_cert.pem` 必须同源 |
| **聊天重复/伪造** | 自己的消息出现两次、能冒充别人 | 不要本地乐观插入；sender 一律由服务端生成；客户端按消息 id 去重 |
| **同步回环** | 远端变更被再次广播回服务端 | `useSync` 的 `applyingRemote` ref：应用远端状态期间抑制本地订阅回发 |
| **设备身份撞车** | 多台手机互相判成「自己」 | 必须用 `identity.ts` 的设备唯一 ID，不要共用写死的 `currentUser.id` |
| **模拟进度条打不中** | `adb input tap` 点击 4px 高的 `.player-progress` 无效 | 真机验证播完切歌用「自然播完」法，别依赖坐标点击 |
| **双音频路径** | 改了真实 `ended` 分支但 Mock 场景没生效 | 切歌/出队逻辑只在 `advance()`，两条路径都要过它 |
| **房间隔离** | 两个房间互收到广播 | 服务端按 `roomId` 分组广播，测试有专项用例，改动 `room.js` 后必跑 `npm test` |
| **assets 未同步** | APK 装上还是旧界面 | `npm run build` 后必须手动拷贝 `dist/*` 到 `android/app/src/main/assets/public/` 再打包 |

## 6. 测试与验证

```bash
# 服务端（13 项：同步 8 + 音乐代理 5）
cd server && npm test

# 前端类型检查 + 构建
npm run build

# 真机日志
adb logcat --pid=$(adb shell pidof com.syncwave.app) | grep -iE "console|chromium|sync"

# 端到端冒烟：起服务端 → 开 App → 设置里连 wss://<电脑IP>:8788 → 开同步开关
# 预期：状态「已连接 · 1人在线」；两台设备互发聊天、互相看到队列/歌曲变化
```

回归清单（改动核心逻辑后建议全过）：
1. 加入房间 → 双端成员列表一致；
2. 一端加歌/置顶/清歌 → 另一端队列同步；
3. 一端切歌 → 另一端同歌从头播；
4. 聊天互发、断线重连不重复、未连接禁言；
5. 最后一首播完 → 队列空态 + 播放条归零停止。
