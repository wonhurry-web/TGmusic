## 1. 产品概述

### 1.1 产品定位

「同频 SyncWave」是一款轻量、高性能的 **一起听音乐** 手机 App。用户可以在线频道中与好友实时聊天、同步听歌，通过多源音乐 API 发现音乐，并用 KTV 式队列共同管理播放列表。

### 1.2 产品 Slogan

> 同一首歌，同一个频率。

### 1.3 核心价值

- **一起听**：多人同步播放进度，共享音乐体验。
- **轻而强**：包体小、启动快、交互流畅，同时功能完备。
- **极简美**：单主页面承载全部核心功能，视觉克制统一。

### 1.4 目标用户

| 画像 | 描述 |
| --- | --- |
| 学生 / 年轻群体 | 喜欢边听歌边聊天，追求社交与陪伴感 |
| 异地恋人 / 好友 | 希望「同步听同一首歌」增强连接 |
| 音乐爱好者 | 需要多平台歌单聚合、日推发现 |
| 聚会场景 | KTV 式队列点歌、切歌、置顶 |

### 2.2 详细功能描述

#### F01 单主页面框架

- 全局仅一个主页面，所有核心功能通过浮层、抽屉、栏目切换承载。
- 顶部栏 + 内容区（三栏）+ 底部播放条三段式布局。
- 适配移动端安全区（刘海、底部 Home 指示条）。

#### F02 已听时长

- 顶部居中显示累计已听歌时长（如「已听 12 小时 34 分」）。
- 数据源：本地统计（每日/累计），预留同步字段。
- 格式：小于 1 小时显示分钟，大于等于 1 小时显示「X 小时 Y 分」。

#### F03 三栏切换

| 栏目 | 内容 |
| --- | --- |
| 推荐 | 各音乐 API 歌单推荐 + 每日推荐（日推） |
| 搜索 | 用户主动搜索歌曲/歌手/歌单 |
| 队列 | KTV 式播放队列：添加播放、切歌、置顶 |

- 顶部标签栏切换，滑动手势辅助。
- 三栏内容独立滚动，切换保留状态。

#### F04 在线频道聊天气泡

- 左上角气泡图标，带未读消息数角标。
- 点击进入「在线频道」群聊界面（类似群组聊天）。
- 消息类型：文本、表情、歌曲卡片（分享到频道）。
- 框架阶段：本地 Mock 会话；后续接入 WebSocket / FRP 同步。

#### F05 设置中心

右上角齿轮入口，进入设置中心，包含：

| 设置项 | 选项 / 行为 |
| --- | --- |
| 音质切换 | 标准 / 高品 / 无损 / Hi-Res（框架阶段仅记录状态） |
| 第三方账号挂载 | 网易云 / QQ 音乐 / 酷狗等账号绑定入口（预留） |
| 主题切换 | 黑白主题（浅色/深色）+ 炫彩主题 |
| FRP 同步 | 开关，后续接入内网穿透同步 |
| 离线开关 | 开关，离线模式与缓存管理 |

#### F06 底部播放条

- 显示当前歌曲封面、歌名、歌手。
- 播放/暂停、上一首、下一首。
- 进度条拖动。
- 点击封面/歌名打开歌词页（见 F13）。

#### F13 查看歌词

- 点击底部播放条的当前歌曲封面/歌名，从底部滑出歌词页。
- 顶部：收起按钮、歌名歌手、分享到频道。
- 中部：随封面渐变旋转的黑胶唱片（播放时旋转）+ 唱臂。
- 歌词区：逐行展示，根据播放进度高亮当前行并自动滚动居中；点击任意行跳转播放进度。
- 底部：进度拖动、播放/暂停、上下曲、时间显示。
- 歌词数据经 `getLyrics()` 抽象层获取（框架阶段 Mock，后续接真实 LRC）。

#### F07 主题系统

- **黑白主题**：浅色（白底黑字）/ 深色（黑底白字）。
- **炫彩主题**：渐变色、动态光效、彩色强调色。
- 基于 CSS 变量实现，切换即时生效并持久化。

#### F08 音乐 API 聚合（待接入）

- 通过统一抽象层接入多个音乐 API。
- 歌单推荐 + 每日推荐。
- 框架阶段：Mock 数据；接入阶段：适配器模式。

#### F09 KTV 队列

- 添加歌曲到队列。
- 切歌（上一首/下一首）。
- 置顶歌曲（提升播放优先级）。
- 队列条目可拖动排序（预留）。

## 3. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 冷启动 < 2s，列表滚动 60fps，包体尽量小 |
| 轻量 | 依赖精简，按需加载，避免冗余库 |
| 美观 | 统一的视觉语言，克制的动效，遵循设计规范 |
| 兼容 | Android 8+（API 26+），Web 现代浏览器 |
| 可维护 | 模块化、文档齐全、API 与 UI 解耦 |
| 可扩展 | 新音乐源、新主题、新功能可通过配置/插件扩展 |
| 调试 | 支持 ADB 真机部署调试 |

---

## 4. 约束与假设

1. 当前阶段只搭建框架，使用 Mock 数据，不接入真实音乐 API。
2. API 通过抽象层接入，后续替换数据源不影响 UI。
3. 一起听的实时同步依赖 FRP / WebSocket，当前仅预留开关与接口。
4. 第三方账号挂载当前仅预留 UI 入口。
5. Android SDK 打包环境后续配置，ADB 调试工具已就绪。
