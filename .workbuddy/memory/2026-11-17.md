## v0.4.1 首页精简 + 队列消耗式推进（完成）

- `App.css` 删除 `.brand-banner` / `.brand-text` / `.banner-spark` 样式，新增 `.recommend-tab { padding-top: 14px }` 补偿首屏呼吸感。

**需求 2：队列消耗式推进（核心改动 `src/store/player.ts`）**
- 新增模块级纯函数 `advance(queue, current)`，手动「下一首」(`next`) 与播完自动切歌（`tick` 模拟路径、audioPlayer `ended` 真实路径）共用同一策略：
  1. 当前曲从队列移除（播完即消耗）；
  2. 剩余队列有置顶 → 从置顶第一首播（KTV 插播）；
  3. 否则按原索引播下一首，队尾环回队首（`rest[idx % rest.length]`）；
  4. 队列仅剩当前一首 → 不删除、progress 归零、`isPlaying: false` 停止（避免 currentTrack 非空类型被破坏）。
- `playTrack` 改为「不在队列则自动入队」，保证播放顺序确定、已播曲可被清除。
- `prev` 修正：idx<=0 时环回到队尾。
- `QueueTab` 提示改为「置顶歌曲优先播放；播完的歌曲自动出队，不占队列」。

**验证**
- 纯函数用例 9/9 通过（中/首/尾曲出队、置顶优先、仅剩一首停止、当前曲不在队列、空队列）。
- 真机（竖屏 1080x2376）：4→3 首手动下一首出队 ✓；置顶第 3 首后切下一首直接从置顶播、原当前曲出队 3→2 ✓；自然播完自动切歌 2→1 ✓。

**踩坑**
- 进度条 `.player-progress` 只有 4px 高（绝对定位 top:-2px），`adb input tap` 极难命中，实测点 1964~1976 全部落空。
- 水平 `input swipe` 会被 App 三栏左右滑动手势（onTouchStart/End）拦截，导致误切 tab，不能用来拖进度。
- `adb shell wm user-rotation lock 0` 才能真正锁竖屏（`settings put system user_rotation 0` 对传感器旋转的 Activity 无效）。
- `PowerShell Add-Type` 被安全策略拦截，无法用 System.Drawing 读像素；环境无 PIL / ImageMagick / ffmpeg。
- 结论：验证自动切歌最可靠的方式是**等待自然播完**（`sleep` + screencap），配合 `svc power stayon true` 防熄屏。
